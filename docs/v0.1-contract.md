# Agent Undo v0.1 contract

Public behavioral contract for **this tree** (unreleased v0.1.1 safety patches).

Tagged `v0.1.0` binaries (`978057f`) do **not** include the three rules below. Do not retag `v0.1.0`. If this document, the README, and a binary built from this tree disagree, that is a **v0.1.1 release blocker**.

This document is authoritative for engineering decisions during the feature freeze. [limitations.md](limitations.md) is the detailed annex. Do not copy a third limitations list into the README.

v0.1 is **frozen** except the authorized v0.1.1 safety patches: spawn-start undo eligibility, `recover --yes` target selection, and `run` refuse of `$HOME`. No Batch 8. No observability, policy engine, agent firewall, cloud, dashboard, Cursor-native attach, new agent adapters, or in-product telemetry. Prebuilt GitHub Release binaries are a distribution pass, not a product capability.

## v0.1.1 safety patches

1. **Undo eligibility.** A session is undoable only when the wrapped process successfully started (`process.Execute` returned `StartErr == nil`). LookPath failure and `cmd.Start` failure are not undoable, even if a checkpoint exists. Started + non-zero exit, started + SIGINT, and started + `FINAL_SNAPSHOT_FAILED` remain undoable.
2. **Recover `--yes`.** Confirmation may be skipped; target selection may not. `recover --yes` without an explicit `cp_…` is refused. `recover` with no id may still select the latest recovery for this repository and require confirmation. `recover --yes cp_…` is valid.
3. **`run` `$HOME`.** `run` refuses when the cleaned working directory equals the user's home directory. Nested paths such as `~/Projects/foo` and `/tmp/foo` are allowed. `doctor` stays inspection-oriented and warns that `run` will refuse `$HOME`.

## Sentence

Agent Undo lets a developer wrap a terminal AI coding session, understand what changed, and safely return to the state from before the session.

## Supported

| Capability | What v0.1 actually does |
|---|---|
| macOS, Linux | Until `v0.1.0`: `go install …@main`. After the tag: GitHub Release binaries (`darwin`/`linux` × `amd64`/`arm64`), SHA-256 in `checksums.txt`. CI executes tests on `ubuntu-latest` and `macos-latest`. Other release targets are cross-compiled, not executed. |
| Git repositories | Captures HEAD, branch or detached HEAD, and checkpointed working-tree bytes. |
| Non-git directories | Filesystem checkpoint only. Receipt: `Git: not captured`. |
| Local filesystem checkpointing | Content-addressed objects + manifest. Gitignored small files such as `.env*` are captured. Bulky trees are skipped by class. See ADR 0003. |
| Session wrapper | `agent-undo run <command>`: refuse if cwd is the user home directory; otherwise lock → verified checkpoint → process group → final manifest → diff → receipt. |
| Diff | `agent-undo diff <session-id>`: path-level delta vs the session checkpoint. |
| Receipt | `run` and `session show` print the same projection of persisted artifacts. |
| Undo | `agent-undo undo [--yes] <session-id>`: restore the session checkpoint. Allowed only when the wrapped process started. |
| Verify | `agent-undo verify <session-id>`: recompute live state vs the session checkpoint. Owns SUCCESS / FAILED / INCOMPLETE. |
| Recover | `agent-undo recover [--yes] [cp_…]`: restore a `kind: recovery` checkpoint. No-argument form (without `--yes`) may select the latest valid recovery for this repository and must confirm. `recover --yes` requires an explicit `cp_…`. |
| Installation | User-level CLI. Not installed into the repository. |
| Repository initialization | None. `init` is not a command. |
| Repository config files | None. Does not create config, store, or ignore files in the repository. |
| Checkpoint store | Global local store: `~/.agent-undo/` or `$AGENT_UNDO_HOME`. Repository-scoped checkpoint and session data lives there, not in the protected tree. |
| Doctor | Inspection only; does not initialize. Prints `checking: <absolute path>` first, then READY / READY WITH WARNINGS / NOT READY. Does not repair. From `$HOME`, warns that `run` will refuse to checkpoint `$HOME`. |
| Protection begins | `agent-undo run <agent>`. |

Canonical commands: `run`, `session list`, `session show`, `undo`, `verify`, `diff`, `recover`, `doctor`.

Session ids look like `XXXXXXXX-XXXXXXXX`. `undo` / `verify` / `diff` / `session show` take session ids and reject raw `cp_…` with a pointer to `agent-undo recover`. `recover` takes only `kind: recovery` checkpoint ids.

## Not supported

| Out of scope | Honest stance |
|---|---|
| Windows | Unsupported. Not a v0.1 launch blocker. |
| Homebrew / `curl \| sh` | Not a v0.1 install path. |
| Git index / staging fidelity | HEAD + checkpointed filesystem bytes only. Staged-only changes may appear unstaged after undo. |
| External side-effect rollback | Email, Slack, cloud APIs, billed usage, purchases, remote git, Kubernetes, DNS, SaaS. |
| Cloud rollback | Not a cloud product. |
| Database rollback | Only if the database was a checkpointed file in the workspace. |
| Production infrastructure rollback | Local workspace only. |
| Cursor / editor-native attachment | Wrapper-based: `agent-undo run <agent command>`. |
| Sandbox guarantees | Runs as the user. Not kernel isolation. Hostile agents can still destroy `$HOME`. |
| Agent ownership inference | Deletes listed in the restore plan. No “the agent created this” heuristic. |
| Arbitrary multi-repo sessions | One repository boundary per session. Nested `run` / `undo` / `recover` fail closed on the lock. |

`keep` is not a command. `init` and `inspect` are not commands.

## Restore invariant

Every destructive restore (`undo` and `recover`) uses one engine, in this order:

```
LOCK → LOAD → VALIDATE → PLAN → RECOVERY CHECKPOINT → APPLY → VERIFY → REPORT
```

```
CURRENT STATE
    ↓
CREATE + VERIFY RECOVERY CHECKPOINT
    ↓
APPLY TARGET CHECKPOINT
    ↓
VERIFY
```

Never APPLY first. Success is printed only after VERIFY. Fail closed. A selected recover target is not silently swapped after lock.

Git movement (when captured): move HEAD to the captured SHA if needed, **then** overlay the checkpoint. Session commits are not deleted. Never force-push, delete branches, or prune.

## Wrapper contract

- Child exit N is preserved. Interrupt: 130. Usage: 1. Internal failure: 3. `run` from the user home directory is usage (1) and does not checkpoint.
- Exit status alone does not attribute failure. Use `session show`.
- Undo is unavailable when the wrapped process did not start, even if a session checkpoint exists.
- Argv is persisted as given. Do not pass secrets as arguments. Environment is not stored.
- stdout/stderr inherit; they are not stored in the session record.
- On cancel: SIGINT → SIGTERM → SIGKILL. Grandchildren are best-effort in the process group.
