# Agent Undo v0.1 contract

Public behavioral contract for the tagged `v0.1.0` CLI.

If this document, the README, and the binary disagree, that is a **launch blocker**. Do not tag until they match.

This document is authoritative for engineering decisions during the feature freeze. [limitations.md](limitations.md) is the detailed annex. Do not copy a third limitations list into the README.

v0.1 is **frozen**. The next work is prove → ship → listen. No Batch 8. No observability, policy engine, agent firewall, cloud, dashboard, Cursor-native attach, new agent adapters, or in-product telemetry.

## Sentence

Agent Undo lets a developer let an AI agent loose on a local workspace, understand what changed, and safely return to the state from before the session.

## Supported

| Capability | What v0.1 actually does |
|---|---|
| macOS, Linux | CI: `ubuntu-latest`, `macos-latest`. |
| Git repositories | Captures HEAD, branch or detached HEAD, and checkpointed working-tree bytes. |
| Non-git directories | Filesystem checkpoint only. Receipt: `Git: not captured`. |
| Local filesystem checkpointing | Content-addressed objects + manifest. Gitignored small files such as `.env*` are captured. Bulky trees are skipped by class. See ADR 0003. |
| Session wrapper | `agent-undo run <command>`: lock → verified checkpoint → process group → final manifest → diff → receipt. |
| Diff | `agent-undo diff <session-id>`: path-level delta vs the session checkpoint. |
| Receipt | `run` and `session show` print the same projection of persisted artifacts. |
| Undo | `agent-undo undo [--yes] <session-id>`: restore the session checkpoint. |
| Verify | `agent-undo verify <session-id>`: recompute live state vs the session checkpoint. Owns SUCCESS / FAILED / INCOMPLETE. |
| Recover | `agent-undo recover [--yes] [cp_…]`: restore a `kind: recovery` checkpoint. No-argument form selects the latest valid recovery for this repository. |
| Doctor | `agent-undo doctor`: READY / READY WITH WARNINGS / NOT READY. Does not repair. |

Canonical commands: `run`, `session list`, `session show`, `undo`, `verify`, `diff`, `recover`, `doctor`.

Session ids look like `XXXXXXXX-XXXXXXXX`. `undo` / `verify` / `diff` / `session show` take session ids and reject raw `cp_…`. `recover` takes only `kind: recovery` checkpoint ids.

## Not supported

| Out of scope | Honest stance |
|---|---|
| Windows | Unsupported. Not a v0.1 launch blocker. |
| Git index / staging fidelity | HEAD + checkpointed filesystem bytes only. Staged-only changes may appear unstaged after undo. |
| External side-effect rollback | Email, Slack, cloud APIs, billed usage, purchases, remote git, Kubernetes, DNS, SaaS. |
| Cloud rollback | Not a cloud product. |
| Database rollback | Only if the database was a checkpointed file in the workspace. |
| Production infrastructure rollback | Local workspace only. |
| Cursor / editor-native attachment | Wrapper-based: `agent-undo run <agent command>`. |
| Sandbox guarantees | Runs as the user. Not kernel isolation. Hostile agents can still destroy `$HOME`. |
| Agent ownership inference | Deletes listed in the restore plan. No “the agent created this” heuristic. |
| Arbitrary multi-repo sessions | One repository boundary per session. Nested `run` / `undo` / `recover` fail closed on the lock. |

`keep` is not a command. `init` and `inspect` are not commands.

## Restore invariant

Every destructive restore (`undo` and `recover`) uses one engine, in this order:

```
LOCK → LOAD → VALIDATE → PLAN → RECOVERY CHECKPOINT → APPLY → VERIFY → REPORT
```

```
CURRENT STATE
    ↓
CREATE + VERIFY RECOVERY CHECKPOINT
    ↓
APPLY TARGET CHECKPOINT
    ↓
VERIFY
```

Never APPLY first. Success is printed only after VERIFY. Fail closed. A selected recover target is not silently swapped after lock.

Git movement (when captured): move HEAD to the captured SHA if needed, **then** overlay the checkpoint. Session commits are not deleted. Never force-push, delete branches, or prune.

## Wrapper contract

- Child exit N is preserved. Interrupt: 130. Usage: 1. Internal failure: 3.
- Exit status alone does not attribute failure. Use `session show`.
- Argv is persisted as given. Do not pass secrets as arguments. Environment is not stored.
- stdout/stderr inherit; they are not stored in the session record.
- On cancel: SIGINT → SIGTERM → SIGKILL. Grandchildren are best-effort in the process group.

## Launch gate

Tag `v0.1.0` only when all of these are true:

- This contract matches implementation and README
- Restore/security audit has no unresolved blockers ([prelaunch-audit.md](prelaunch-audit.md))
- Demo fixture is deterministic; `examples/setup-demo` and `--check` succeed
- README works from a repository checkout
- Clean-machine journeys A–D completed by a human
- Limitations are truthful
- The `v0.1.0` tag is reproducible

Then tag and stop. No Homebrew, install script, or announcement campaign in v0.1 launch.
